# 70.757에서 확인한 내부 입력 경로

분석 입력은 사용자가 제공한 `brawlstars-70.757-backup` 릴리스의 ZIP입니다. ZIP SHA-256:

`8e1f184645198723018aa2d89cca5842925cf9a618fa1182d92aeb2ddebd34ea`

6개 분할 APK의 서명 검증은 모두 성공했고 같은 인증서를 사용했습니다. 원본 인증서 SHA-256은 `731a29e80b7ca89c7e9b39d381821ee8dccd1b0456782f788650945e7d60d8d3`입니다. 이는 제공 파일의 서명 일치 확인이며 사용자가 가진 모든 다른 버전의 호환성을 뜻하지 않습니다.

## Java / JNI 경로

원본 매니페스트의 Application은 `com.supercell.titan.TitanApplication`, 시작 Activity는 `com.supercell.brawlstars.GameApp`입니다. 후자는 `com.supercell.titan.GameApp`을 상속합니다.

원본 `GameApp.getView()`는 `GL2JNISurfaceView`를 반환합니다. 해당 뷰의 입력 처리는 정적 네이티브 메서드 `nOnTouchEvent(int type, int x, int y, int pointerId)`를 UI 스레드에서 호출합니다.

| 이벤트 | 원본 JNI type | 좌표 / 포인터 |
| --- | --- | --- |
| 누름 | 0 | 원본 뷰 좌표 × 렌더링 배율, 포인터 ID |
| 이동 | 2 | 각 포인터의 좌표 × 렌더링 배율, 포인터 ID |
| 뗌 | 1 | 원본 뷰 좌표 × 렌더링 배율, 포인터 ID |
| 취소 | 3 | 0, 0, 0 |

원본 뷰는 `getScaleX()/getScaleY()`를 오버라이드하여 자체 렌더링 배율을 제공합니다. 이 모듈은 그 배율로 계산한 렌더링 크기에 정규화된 제어 위치를 대응시킵니다. 캐릭터 이동·슛을 수행하는 더 깊은 게임 함수를 찾았다고 주장하지 않습니다. 확인한 기존 JNI 입력 진입점을 호출합니다.

## 추가한 부분

1. exported=false ContentProvider로 Activity lifecycle 콜백을 등록합니다.
2. 원본 Activity의 장식 뷰에 ON/OFF 버튼을 추가합니다. 시스템 오버레이 창은 만들지 않습니다.
3. 원본 SurfaceView에 PixelCopy를 요청합니다. 별도 MediaProjection 세션이나 다른 앱의 화면 접근은 없습니다.
4. 제공된 Iris 모델·화면 템플릿을 이용해 960×540 좌표계에서 판단합니다.
5. UI 스레드에서 위 JNI 메서드를 reflection으로 호출합니다. 포인터 9를 사용하고 수동 입력은 자동 입력을 취소합니다.

새 네이티브 라이브러리는 ONNX Runtime 2개와 OpenCV 1개입니다. 게임의 `libc++_shared.so`는 유지했습니다. OpenCV가 참조하는 C++ 심볼 223개가 원본 런타임에 존재하는 것을 ELF 심볼 표로 확인했지만, 이것만으로 실행 중 ABI 호환성이 증명되는 것은 아닙니다.

## 확인하지 않은 것

게임의 실행 무결성 정책, 서버의 허용 버전, 실제 폰의 SurfaceView 캡처 허용, 실제 경기에 대한 인식 정확도는 정적 분석으로 검증되지 않습니다. APK의 원본 DEX/자산을 유지해도 서명과 컨테이너가 달라지므로 게임이 실행을 거부할 수 있습니다. 검증 기록에 친선전투 0회를 명시했습니다. 자동 패치·서명·오프라인 테스트 성공을 실전 성공으로 해석하면 안 됩니다.
